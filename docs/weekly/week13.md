## 3. 정할 것

**채팅 범용 경로를 에이전트로 (12주차 3절 "이후 검토"에서 이어짐)**
- 범위(안): 라우터 마지막 줄("그 외 → 검색 → 추천")만 에이전트 경로로. 상세·비교·되묻기·범위 밖은 지금 라우터 그대로 (빠르고 확실함). 같은 검색 → 추천으로 가는 복합 질문(하위 질문 2개 이상)도 넣을지, 분석 실패는 기존 경로로 둘지
- 방식: 에이전트가 정책만 고르고 답변은 기존 생성기가 스트리밍할지(SSE·저장·평가 형식이 그대로), 에이전트가 답변까지 만들지(채팅용 출력 모양과 스트리밍을 새로 맞춰야 함)
- 실패하면(도구 루프 오류, 시간 초과) 기존 검색 → 추천 경로로
- 채팅 SSE 형식(`policies`, `token`, `done`)과 저장 형식(답변 metadata·카드)을 그대로 맞출지, 에이전트 출력 모양을 채팅용으로 따로 둘지
- 속도: 에이전트 턴은 중앙 약 4.5초, 지금 추천 경로 첫 글자는 약 5초. 첫 글자가 늦어지지 않게 하는 방법
- 비교 방법: 같은 질문 세트로 기존 경로와 에이전트 경로를 나란히. 주관적 기준 질문은 12주차 비교에서 에이전트가 나았음

**회귀 평가**
- 평가 서버 질문 세트(라우팅 `routing_v1` 90건, 답변·검색 `golden_v2` 100건)로 v8과 v10을 나란히 (라우팅 혼동 행렬, 카드 재현율). Titan 기준점이 없어서 v8도 같은 조건으로 다시 돌림. 평가 서버 쪽에 Titan 결과가 있으면 그것을 씀
- 돌릴 범위·횟수 (비용): 라우팅은 두 버전 모두, `golden_v2`는 횟수를 줄일지
- `local_only`는 라우팅 세트에 없는 필드라 12주차 시험 세트(44개)로 확인한 것으로 갈음
- 범용 경로를 바꾼 뒤 한 번 더 돌림

**관찰에서 이어진 것**
- 현재 정책이 둘일 때 이름 없이 "신청 기간은?": 되묻기(10주차 정답)와 둘 다 답하기 중 어느 쪽을 정답으로 둘지

## 4. 작업 순서 (안)

| 순서 | 작업 | 최소 완료 기준 |
|---|---|---|
| 1 | 회귀 평가 1 | 평가 서버 질문 세트로 v8과 v10을 나란히. v10에서 떨어진 유형이 없거나, 있으면 틀린 샘플로 원인 확인 (되돌리기는 `PROMPT_NAME` 한 줄) |
| 2 | 배포 | 운영 DB에 022 먼저 → 서버 배포 → 운영에서 채팅·추천 에이전트·PDF·스크랩 한 바퀴 |
| 3 | 팀원 전달 | 프론트 mock 걷기(에이전트 API 실제 연결, 질문 없는 턴에도 직접 입력, v1.4 보충), ETL 지역 데이터 확인 거리 (광양시 정책 4개가 전국 지역 코드, 경기 프로필에 충청북도 취업박람회 등). 프론트·평가 서버·인프라가 한 사람이라 묶어서 전달 |
| 4 | 범용 경로를 에이전트로 (PR) | 3절 정한 뒤 구현. 실패하면 기존 경로, trace는 채팅 형식 |
| 5 | 회귀 평가 2, 다시 배포 | 4번을 넣은 상태로 질문 세트 + 기존 경로와 나란히 비교. 떨어지지 않으면 배포 |

- 시연할 수 있는 상태(1~3)를 먼저 운영에 두고, 채팅 흐름을 바꾸는 4번은 그 뒤에 함. 4번이 늦어져도 시연은 12주차 상태로 가능
- 4번은 main에서 새 브랜치
