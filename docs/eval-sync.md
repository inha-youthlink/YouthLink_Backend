## 3. RAG 담당 확인 사항에 대한 답
| 확인 | 답 |
|---|---|
| 평가 대상 서버와 DB | 아직 배포 전. 배포 서버와 DB가 정해지면 `RAG_BASE_URL`과 함께 알림 |
| 라우터가 유형만 보고 핸들러를 고르는지 | 유형 + 지목 여부(앞 턴의 카드를 가리켰는지, 없는 번호인지) + 조건 불일치(#35). `routing_v1`처럼 앞 턴·프로필 없이 보내면 유형만으로 정해지고 라우터는 코드라 백엔드 단위 테스트로 확인함 → **핸들러를 채점하지 않는 결정에 동의.** 프로필이 들어가면 조건 추출(질문의 지역·나이 → 되묻기)이 유형 외 기준이 되므로 P2로 봄 |

| debug 응답에 `filtered_policy_nos` | 추가함 (#37). 필터 없음 `null`, 통과 없음 `[]` |

## 4. 백엔드 제안
### P1. 골든 데이터셋에 프로필 넣기 (`golden_v2`) — 중요
- **이유**: #35부터 정책은 **프로필로만** 거른다. 지금 `golden_v1` 100건은 모두 프로필이 비어 있어, 평가가 1차 필터·되묻기를 전혀 거치지 않는 경로(필터 없이 전체 검색)만 잰다. 실제 서비스는 프로필 8항목이 필수라 이 경로를 타지 않는다
- **코드는 이미 지원**: `GoldenSample.profile`을 그대로 `/internal/pipeline`에 보내므로 데이터(`profile` 값)만 채우면 된다
- **형식**: `profile`은 백엔드 `Profile` 필드 그대로. 빈 필드는 그 조건으로 거르지 않으므로 필요한 항목만 넣어도 됨
  - `region_code`: 법정 시군구 코드 5자리 (`"11680"` 서울 강남구). 시도 전체는 `"41000"`, 구가 있는 시(수원시)는 시 코드·구 코드 모두 시 전체로 봄
  - `age`: 만 나이
  - `job_code`, `school_code`, `marriage_status_code`, `major_code`, `special_target_code`: 정책 데이터 공통코드 (`common_code`, 예: 미취업자 `0013003`, 대학 졸업 `0049007`)
  - `annual_income`: 원 단위 (공개 API의 만 원 단위와 다름)
- **주의**: 프로필이 정답 정책의 자격과 맞아야 한다. 맞지 않으면 1차 필터가 정답 정책을 빼는데, 이건 정상 동작이라 오답으로 세면 안 된다 (`filter_hit` = 0인 샘플은 프로필부터 확인)
- **주의**: 프로필이 질문 내용과도 맞아야 한다. 질문의 지역("부산 금정구 …")·나이("29살")가 프로필과 다르면 되묻기로 가서 채점되지 않고, 취업 상태·학력("구직자로서")이 다르면 프로필 기준으로 찾은 뒤 답변 끝에 차이를 알려 정답과 어긋날 수 있다. "20대 후반"처럼 범위로 말한 나이는 비교하지 않는다

### P2. 조건 되묻기 응답은 RAGAS 채점에서 빼고 경로로 판정
- 되묻기 응답은 근거·카드가 없는 고정 문구라 RAGAS 지표가 의미 없다. 조건 되묻기면 채점에서 빼고, "되물었는지"만 따로 센다
- 판정: `trace.handler = "clarify"`이고 `trace.clarify_reason = "condition"`. `clarify_reason`은 지금 `rag_client.TRACE_DETAIL_KEYS`에 없어 저장되지 않으므로 키를 추가하거나, 이미 저장되는 `handler` + `conditions.mismatches`(`asks_back`이 true인 항목이 있음)로 판정
- 되묻기가 맞게 나오는지 보려면 프로필과 **다른 지역·나이를 말한 질문**을 몇 건 넣고 기대 경로를 되묻기로 둔다 (예: 서울 강남구 프로필 + "인천에서 창업 지원 받을 수 있어?", "35살인데 받을 수 있는 주거 지원 있어?"). 백엔드 개발 평가 세트도 같은 방식으로 2건을 되묻기로 판정함

| A1 | 프로필을 넣는 방식 (P1) | 샘플마다 **정답 정책의 자격과 질문 내용에 맞춰** 만든다 (`policy` 조건으로 자동 생성 가능). 질문에 지역이 없는 전국 정책은 대표 지역을 돌려 쓰고, 정답이 "자격이 안 된다"인 샘플은 프로필을 붙이지 않는다. 대표 프로필 몇 개로만 하면 정답이 필터에서 빠지거나 되묻기로 가는 샘플이 많아짐 |
